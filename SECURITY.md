# Security Policy

## Reporting a vulnerability

Please do not disclose suspected security vulnerabilities in a public GitHub issue.

Report the issue privately to the repository owner, **[@KenlikDev](https://github.com/KenlikDev)**, through GitHub. Include enough detail to reproduce the issue safely, the affected component or endpoint, and any known security impact.

For credentials or secrets accidentally committed to the repository, rotate or revoke the affected credential first when possible, then report the exposure privately.

## Supported versions

Security fixes are applied to the current production line represented by `main`. Older snapshots and feature branches are not treated as supported release lines unless explicitly documented otherwise.

## Disclosure

Please allow reasonable time for investigation, remediation, testing, and release coordination before publicly disclosing a vulnerability.

Once a fix is available, the project may publish a security advisory or release note describing the issue and remediation without exposing unnecessary exploit details.
